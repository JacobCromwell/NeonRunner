# Questions from I3 (the shop on a phone's screen; the iPhone without music)

## 1. Should the web demo play through an iPhone's ring/silent switch?

**The question** (GDD §11, sound; the web demo, §2): Safari mutes everything the demo plays (it all goes
through Web Audio: music and effects) while the phone's ring/silent switch is on, unlike a video, which
plays through it. The page can ask Safari to treat its audio as "playback" (`navigator.audioSession.type`),
and then the demo plays with the switch on, as most web games and videos do. The cost: a player who wants
silence has to turn the volume down (Settings has the sliders), and starting the demo's sound stops another
app's audio (a podcast, a music player) on the phone, which "playback" does by Safari's own rules. Does the
owner want the demo to play through the switch?

**The placeholder:** it does. `html/head_include` of the "Web (demo)" preset in `export_presets.cfg` sets
`navigator.audioSession.type = 'playback'` where the browser has the Audio Session API (and does nothing
elsewhere), marked `DESIGN-TBD`. Removing the `<script>` block makes the demo obey the switch again.

## 2. Should the web demo's music be played as a stream, or lighter, on phones?

**The question** (GDD §11; the web demo, §2): on the web, Godot plays every sound as a "sample" by default
(`audio/general/default_playback_type.web` is Sample): a track is decoded in full when it first plays and
kept as raw sound in the browser's memory, and Godot's web code copies it again each time the track starts.
The demo's Zone 1 song (154 s) is 52 MB that way and the Boss 1 song (180 s) 60 MB, with another copy of
each in the browser while it plays, and the decoding of a whole song is a stop of the game's one thread (0.3 s
on a desktop, likely 1 to 3 s on a phone). A phone short of memory could drop the music or reload the page
(a likely reason one playtester's iPhone had none; the silent switch is the likelier). The other way,
"Stream" (`AudioStreamPlayer.playback_type`, music only), plays a track as it's decoded, with none of that
memory, and also makes the death dip's low-pass work on the web (the Music bus's effects don't apply to
samples), but without threads it mixes on the page's own thread, so a phone drawing under about 20 frames a
second could crackle. A third way is a smaller copy of the songs for the web build (mono, or 22 kHz). Which
does the owner want, if any? It needs a try on a real iPhone either way.

**The placeholder:** none built; music stays as it was (samples), because each choice trades one problem for
another and needs a real phone to judge.
